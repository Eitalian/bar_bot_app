## Критерии handoff между задачами

См. раздел **«Handoff-чеклист задачи»** в `CLAUDE.md` — план соблюдает его без изменений. Для удобства повторим пункт 6:

> Файл вне секции «Карта файлов» — не автоматический стоп, но требует явного обоснования в отчёте агента (ссылка на Step плана, где это предусмотрено). Файл без обоснования → reviewer отклоняет.

**План — каркас, не догма.** Если в ходе исполнения задача требует отступления (иная сигнатура, дополнительный файл, изменённый порядок шагов, иной выбор библиотеки) — это допустимо. Но агент **обязан** в отчёте о handoff явно подсветить: что отклонилось от плана, почему, и какие последствия для следующих задач. Незаявленное отклонение → reviewer отклоняет.

## Pre-PR проверка автора плана (REQUIRED перед коммитом плана)

Перед тем как открыть PR на сам план или передать его субагент-диспетчеру, проверь визуально:

- [ ] Секция **Goal** заполнена (одно предложение, что работает после фазы).
- [ ] Секция **Branch** содержит конкретное имя ветки.
- [ ] **Карта файлов** перечисляет все файлы, упомянутые в Steps (включая ancillary: codebase.md, routes/*.php, фабрики).
- [ ] **Порядок исполнения** присутствует и каждая параллельная группа имеет однострочное обоснование.
- [ ] У каждой задачи есть **Depends on:** (`None` или ссылка на Task M).
- [ ] У каждой задачи есть секция **Files:** (Create / Modify).
- [ ] План — каркас, не имплементация: нет тел методов и тел миграций. Фиксированы только cross-boundary контракты — DDL колонок, имена route-patterns, имена классов/файлов между задачами. Внутренние сигнатуры заданы поведенчески (что вход/выход, кто вызывает), синтаксис выбирает исполнитель.
- [ ] Финальная задача содержит Step «Обновить codebase.md» и Step «Открыть PR».

Не пройденная галочка — план возвращаем на доработку, не запускаем фазу.
