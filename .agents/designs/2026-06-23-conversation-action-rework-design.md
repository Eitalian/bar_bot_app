# Conversation × Action: пересмотр инварианта и двухшаговых флоу — Design Spec

**Date:** 2026-06-23
**Status:** Draft / отложено до завершения BB-12 (разделение транспортов)
**Происхождение:** вынесено из дизайна BB-12 — это отдельная архитектурная тема, не нужная для разделения транспортов. См. `2026-06-23-bb12-ui-transport-split-design.md`.

---

## 1. Зачем отдельная задача

Разделение транспортов (BB-12) — структурное: оно режет совмещённый Action на HTTP-класс и Telegram-точку входа и не меняет поведение. Темы ниже — другое: они пере-решают **архитектурный вопрос Conversation × Action** и **меняют контракт callback_data**. Смешивать их с BB-12 нельзя — это:

- раздувает дизайн BB-12 материалом, не относящимся к транспортам;
- меняет поведение Telegram-UI (контракт `callback_data`), нарушая принцип BB-12 «поведение идентично»;
- трогает долгоживущую спеку `conversation-action-architecture.md` поверх ещё не устоявшейся структуры срезов.

Поэтому всё это живёт здесь и делается **после** BB-12, когда структура срезов уже зафиксирована.

---

## 2. Тема 1: убрать хоп Conversation → Action

**Сейчас** (и после BB-12): Conversation на финальном шаге зовёт Telegram-точку входа через `app(...Action)->fromTelegram(...)`, которая зовёт Handler. Это закреплено в `conversation-action-architecture.md` (инвариант «Conversation не зовёт Handler напрямую»).

**Предложение:** разрешить Conversation звать Handler напрямую, убрав промежуточный хоп. Обоснование: после BB-12 рендер вынесен в Keyboard-классы, а семантику владеет Handler — промежуточный Action не даёт ничего сверх прямого вызова Handler.

**Гарантия, которую надо явно перенести:** старый инвариант существовал, чтобы два транспорта (HTTP и финальный шаг Conversation) не разъехались в поведении. Снимая запрет, гарантию переносим в Handler: **Handler — единственный владелец семантики use-case; оба транспорта обязаны ходить через один и тот же Handler.**

**Дедупликация по месту:** отдельный shared Action заводим **только** если идентичный финальный side-effect реально достижим из двух точек входа (standalone-callback + конец Conversation). Это дедупликация по факту, а не стоячее правило.

## 3. Тема 2: двухшаговые callback-флоу → Conversation

Флоу вида «шаг 1: показать промежуточный UI → шаг 2: выполнить действие» моделируется как Conversation, даже без текстового ввода. Пример — `PlaceOrder` (сейчас живёт как `Action::fromTelegram` + `Action::confirm` на одном классе).

```
app/UI/Telegram/Orders/PlaceOrder/PlaceOrderConversation.php
```

Регистрация:
```php
$bot->onCallbackQueryData('recipe:{id}:order', function (Nutgram $bot, string $id): void {
    PlaceOrderConversation::begin($bot, data: ['recipeId' => $id]);
});
```

Шаги: step 1 — пикер количества (`editMessageReplyMarkup`), step 2 — `order:pick:{n}` → собрать DTO → Handler → notify managers → `end()`.

**Смена контракта callback_data:** `recipe:{id}:order:{qty}` → `order:pick:{n}`. Кнопки количества используют незарегистрированный глобально паттерн `order:pick:{n}`, поэтому попадают в шаг 2; «🔙 Назад» (`recipe:{id}:show`) — глобальный роут, срабатывает funnel escape.

> **Внимание — это смена поведения.** Stale-кнопки `recipe:{id}:order:{qty}` в старых чатах не получат обработчика. При необходимости — добавить fallback-роут. Именно из-за этой смены контракта тема вынесена из BB-12 (там поведение обязано быть идентичным).

**Правило:** `[Class, 'method']` с несколькими callback-входами на одном классе — не использовать. Это пережиток, который рерайт убирает.

## 4. Тема 3: рерайт `conversation-action-architecture.md`

После принятия тем 1–2 переписать спеку `conversation-action-architecture.md`:

- снять инвариант «Conversation не зовёт Handler напрямую» и его review-маркер (`grep -rn "app(.*Handler::class)" app/Telegram/ → 0 совпадений`);
- зафиксировать новый набор инвариантов (Handler — владелец семантики; оба транспорта через один Handler; zero business logic в точках входа и Keyboard; рендер финального результата — в Keyboard);
- старую версию пометить deprecated/archived с указанием на новую.

Сделать это **один раз**, когда находки по двухшаговым флоу и срезам уже устоялись.
